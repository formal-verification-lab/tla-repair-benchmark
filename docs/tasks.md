# Четыре задачи основного эксперимента

Выбор зафиксирован в `configs/tasks.json` до генераций основной модели на этих
задачах. Все четыре — Gold, категория `system`, из TLA+-Bench, ветка
`dataset-release`, commit `ae4b96b1ed2fa6c455488225d727449c267354a9`.

| ID | Модуль | Уровень источника → проекта | Что проверяет исходный cfg | Состояний Gold | Участник |
| --- | --- | --- | --- | ---: | ---: |
| easy_01 | HourClock | basic → easy | HCini | 12 | 1 |
| easy_02 | AsynchInterface | basic → easy | TypeInvariant | 12 | 2 |
| medium_01 | Barrier | intermediate → medium | TypeOK, BarrierProperty | 64 | 1 |
| medium_02 | CigaretteSmokers | intermediate → medium | TypeOK, AtMostOne | 6 | 2 |

Здесь `basic` соответствует лёгкому уровню, `intermediate` — среднему.
Это явное соответствие исходных меток, а не новая оценка сложности по числу
состояний. Категории и исходные пути сохранены в конфигурации выбора.
Небольшое число состояний делает проверку быстрой, но не определяет сложность
выражений TLA+ для модели.

HourClock моделирует циклические часы; AsynchInterface — асинхронный обмен;
Barrier — барьер для нескольких процессов; CigaretteSmokers — координацию
участников с ограниченными ресурсами. Критериями отбора были исходные уровни,
наличие работающей пары Gold/cfg, конечная модель и отсутствие внешних модулей,
кроме стандартной библиотеки TLA+. Ответы LLM для отбора не использовались.
Условия и имена проверяемых свойств взяты из исходных конфигураций без правок.

## Локальная подготовка

В [README источника](https://github.com/LUC-AI4FM/tla_benchmark/blob/ae4b96b1ed2fa6c455488225d727449c267354a9/dataset_release/README.md)
указано ограничение публичного перераспространения сырых файлов.
Поэтому этот публичный репозиторий хранит только указатели, метаданные,
хеши и код загрузки. Спецификации, исходный manifest и описания материализуются
в игнорируемом Git каталоге `data/tasks/` для локальной учебной работы.
Публикация архива с этими файлами потребует отдельной проверки прав источников.

После установки проекта выполните из корня репозитория:

```sh
.venv/bin/python -m benchmark.task_dataset --jar data/lora-pilot/tla2tools.jar
```

Можно передать другой локальный путь к официальному `tla2tools.jar` версии 1.7.4;
его SHA256 должен совпасть с `jar_sha256` в конфигурации. Команда не обращается
к LLM и не использует API-ключи. Python-код берётся из репозитория; Java должна
быть доступна через `java` в PATH.

Подготовка проверяет SHA256 удалённых файлов и неизменность исходных меток,
сохраняет описание из поля `desc_declarative_gpt`, Gold, cfg и метаданные,
запускает SANY, затем TLC, и проверяет число состояний Gold. Низкоуровневая
Java-проверка переиспользуется из модуля подготовки синтетических данных;
это офлайн-проверка набора, а не новый конкурирующий верификатор runner.

Готовый набор появляется атомарно только после успеха всех четырёх задач.
При неудаче сохраняются диагностика и `failure.json` в `data/tasks-failed-…`,
а доступного runner набора не возникает. Повтор команды проверяет сохранённые
хеши без перезаписи или повторной загрузки. Изменённый набор отклоняется.

## Граница доступа к Gold

В `data/tasks/<id>/` находятся `description.md`, `Spec.cfg`, `metadata.json`,
каталог `reference/` и диагностические файлы `gold-check/`. Сводка и хеши
всех материалов находятся в `data/tasks/prepared.json`.

`load_inputs(selection, directory)` возвращает только общие `TaskInput`:
ID, имя модуля, описание и cfg. Проверяется квитанция успешной подготовки и
контрольные суммы входного текста. Эта функция не открывает `reference/`,
не читает Gold и не извлекает из него подсказки. Отдельная `inspect_prepared`
проверяет весь локальный набор, включая Gold, только при офлайн-аудите.

## Ограничения исследования

Проверки Gold выполнены на закреплённом JAR без изменения cfg. Сохранены сырые
логи, команды, версия Java и хеш кода проверки. Это подготовка набора;
обязательные 12 прогонов ещё не выполнены.

Исходные проверки лёгких задач в основном проверяют типизацию. Успешный TLC
и совпадение числа состояний не доказывают соответствия поведения исходному
описанию. Четыре классические задачи из одного upstream-репозитория — малая
выборка; их присутствие в предобучении модели не исключено. Основная модель —
GigaChat; локальный адаптер LoRA в этих прогонах не используется.
