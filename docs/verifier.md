# Верификатор SANY/TLC

`benchmark.verifier.JavaVerifier` реализует общий `Verifier` без изменения
контрактов. Каждая проверка получает новый каталог; существующий каталог
отклоняется, результаты не перезаписываются. В него копируются только переданные
спецификация и cfg. Gold автоматически не читается.

Используется официальный [TLA+ tools 1.7.4](https://github.com/tlaplus/tlaplus/releases/tag/v1.7.4),
как и при подготовке задач. Перед запуском проверяется переданный SHA-256.
Java должна быть установлена отдельно. Запуск из корня проекта:

```sh
python -m benchmark.verifier \
  --spec /absolute/path/AsynchInterface.tla \
  --cfg /absolute/path/Spec.cfg \
  --jar /absolute/path/tla2tools.jar \
  --jar-sha256 936a262061c914694dfd669a543be24573c45d5aa0ff20a8b96b23d01e050e88 \
  --output runs/check-001
```

Код завершения CLI: 0 только при успехе обеих проверок, 1 при неуспешной
проверке. Ошибки входных файлов и сохранения прерывают выполнение.
`--sany-timeout` и `--tlc-timeout` задают независимые положительные лимиты
в секундах, по умолчанию 30 и 60.

SANY запускается первым. TLC запускается только после положительной диагностики
семантической обработки основного модуля и нулевого кода SANY. Известные сообщения
об ошибках SANY имеют приоритет над маркером семантической обработки: SANY 1.7.4
может вернуть нулевой код при ошибке спецификации.

Для успеха TLC нужны нулевой код и явное сообщение о завершении проверки без
ошибок. Распознанные нарушения инварианта, deadlock и временных свойств имеют
категории; другие распознанные ошибки спецификации оставляют категорию null.
Неизвестное завершение считается `tool_error`, а не успехом. Исключения среды,
включая нехватку памяти и ошибки Java RMI/сети, считаются техническими сбоями.
Таймаут — отдельный статус, частичный вывод сохраняется.

Параметры Java фиксированы: heap 512 MB, SerialGC. TLC работает с одним worker,
не отключает deadlock, не меняет cfg и сохраняет полный контрпример в stdout.
В Python-интерфейсе `tlc_arguments` разрешены только пары `-workers` и `-seed`;
режим симуляции, восстановление предыдущего запуска и отключение проверок
отклоняются. Настройки следует зафиксировать до основных экспериментов.

## Артефакты

- `environment.json`: настройки, SHA-256 JAR/входных файлов, версия Java,
  полный ответ `tlc2.TLC -help` с версией инструментов.
- `sany.stdout.log`, `sany.stderr.log`, аналогичные файлы TLC: точные байты вывода.
- `sany.json`, `tlc.json`: команда, статус, код завершения, время по монотонным
  часам, полный декодированный вывод. При пропущенном TLC отдельного файла нет.
- `verification.json`: общий `VerificationResult`, включая `not_run` для TLC
  после неуспешного SANY.
- Копии входных `.tla`/cfg и рабочие файлы TLC в `states/`.

Исходные байты логов сохраняются без изменений; для JSON используется UTF-8
с заменой недопустимых последовательностей. Дополнительные пользовательские
модули вне стандартной библиотеки пока не поддерживаются. Классификация текстовых
диагностик рассчитана на закреплённый JAR; неизвестную диагностику требуется
разбирать отдельно. Успех TLC не доказывает соответствия исходному описанию задачи.

Диагностика TLC `The name ... specified in the configuration file is not defined
in the specification` (код 151 в закреплённом JAR) относится к
`spec_error / configuration`: модель должна определить оператор из фиксированного
cfg. Это не инфраструктурный сбой. Регрессионная проверка выполняет настоящий
TLC, а тест runner проверяет продолжение исправлений A/B/C. Результаты старых
серий не переклассифицируются на месте; расхождения отмечаются отдельным аудитом.

## Проверки

```sh
TLA_TOOLS_JAR=/absolute/path/tla2tools.jar pytest tests/test_verifier.py
```

Проверяются реальные корректная спецификация, синтаксическая/семантическая ошибка,
нарушение инварианта, deadlock, нарушение временного свойства, неполное
начальное состояние и таймаут. Без переменной Java-проверки явно
пропускаются. Отдельный CI job скачивает закреплённый официальный JAR,
проверяет SHA-256 и выполняет эти проверки с Java 17.

Локальная проверка этапа 5 ноября 2026: Java Temurin 18.0.2, официальный JAR
с указанным SHA-256; полный набор из 87 тестов, включая восемь реальных
Java-сценариев. Дополнительно этим верификатором проверены Gold easy_02
(AsynchInterface) и medium_02 (CigaretteSmokers): SANY/TLC прошли.
Это проверки инфраструктуры и Gold, а не экспериментальные прогоны LLM.
