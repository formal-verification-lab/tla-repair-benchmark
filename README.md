# TLA+ Repair Benchmark

Учебный и исследовательский проект, вариант №2: сравнение полного лога,
фильтрованного лога и объяснения LLM при исправлении спецификаций TLA+.

Реализованы CLI, общие Python-контракты и локальный клиент Ollama с записью
вызовов. SANY/TLC, стратегии и запуск экспериментов относятся к следующим этапам.
Результатов эксперимента пока нет.

## Установка и проверка

Требуется Python 3.12 или новее. На macOS с несколькими версиями Python
укажите нужный интерпретатор явно, например `python3.12`.

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
tla-repair --help
tla-repair schema-info
python -m benchmark schema-info
ruff check .
ruff format --check .
pytest
```

Java и `tla2tools.jar` для проверок каркаса не нужны. Их установка и фиксация
версий входят в этап верификатора. API-ключи не требуются и не хранятся в Git.

## Совместная разработка

Один этап — одна ветка — один PR; второй участник проверяет изменения.
Контракты: `src/benchmark/contracts.py` и `docs/contracts.md`.

Участник 1: клиент LLM, runner, интеграция, Easy 1 / Medium 1.
Участник 2: верификатор, стратегии, метрики, Easy 2 / Medium 2.
Общие интерфейсы меняются явно с обновлением документации и потребителей.
Синхронные `Protocol` допускают подмену реализаций в тестах без API и Java.

Идентификаторы методов в файлах: `A`, `B`, `C` (русские обозначения: А, Б, В).
Для локального запуска выбрана Qwen3.5-4B (`qwen3.5:4b`).
Выбор задач и фиксация параметров основных экспериментов ещё предстоят.

## Данные и ограничения

Gold используется только при подготовке и последующем аудите; `TaskInput`
его не содержит. Успех SANY/TLC не доказывает соответствия описанию задачи.
12 обязательных прогонов предшествуют расширению до 36. Данные пилота
хранятся отдельно. Неуспехи и технические сбои отражаются явно.

## Локальная модель

На macOS установите Ollama и запустите сервер в отдельном терминале:

```sh
brew install ollama
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 OLLAMA_NUM_PARALLEL=1 OLLAMA_MAX_LOADED_MODELS=1 OLLAMA_FLASH_ATTENTION=1 OLLAMA_KV_CACHE_TYPE=q8_0 ollama serve
```

В другом терминале загрузите модель и выполните пробный вызов:

```sh
ollama pull qwen3.5:4b
printf '%s\n' '[{"role":"user","content":"Reply with exactly OK."}]' > /tmp/tla-messages.json
tla-repair ollama-chat --messages /tmp/tla-messages.json --output results/smoke --max-output 32
```

Это проверка API, а не эксперимент с TLA+. CLI по умолчанию использует
контекст 8192, выход до 2048 токенов, temperature 0.7 и отключённое thinking.
Параметры доступны через `tla-repair ollama-chat --help`; они не являются
зафиксированным исследовательским протоколом. После вызова `keep_alive=0`
выгружает модель, освобождая память для TLC.

Каждый вызов получает новый каталог `calls/<call-id>/`: запрос, версия сервера,
метаданные и digest модели, исходный ответ и результат либо ошибка. Данные
записываются до сетевого запроса; ошибка записи останавливает вызов. История
передаётся только явно, автоматических повторов нет. Для фиксации весов
используйте `--expected-digest` со значением из `environment.json`.
Каталоги `results/` локальны и не коммитятся автоматически.

Клиент запрещает облачные модели, отключает обрезание входа и сдвиг контекста.
Ошибки сервера и незавершённые ответы сохраняются как ошибки. При наличии
обоих счётчиков клиент проверяет сумму входных и выходных токенов: превышение
`num_ctx` сохраняется как ошибка даже если сервер вернул HTTP 200. Это проверка
после генерации: Ollama 0.40.7 с MLX на реальном запросе принял вход длиннее
заданного окна. Она не предотвращает расход памяти и токенов; без usage
подтвердить соблюдение окна нельзя.
Завершение по лимиту выхода сохраняет текст и `done_reason` в исходном ответе;
оно не означает успеха верификации. Пустой завершённый ответ тоже возвращается,
чтобы runner учёл неудачную генерацию как попытку. Неизвестный usage остаётся `null`.
Полный ответ, включая thinking при его включении, хранится на диске, в поле
`LLMResponse.text` передаётся только окончательный текст.

API: [chat](https://docs.ollama.com/api/chat),
[локальные модели и digest](https://docs.ollama.com/api/tags).
